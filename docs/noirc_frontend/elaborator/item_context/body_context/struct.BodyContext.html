pub(crate) struct BodyContext {
    current_loop: Option<Loop>,
    lambda_stack: Vec<LambdaContext>,
    unsafe_block_status: UnsafeBlockStatus,
    in_unconstrained_args: bool,
    silence_field_visibility_errors: usize,
    lvalue_index_counter: usize,
}
Expand description

Where in a function body the elaborator currently is.

Every field here belongs to a scope nested inside the item - a loop, an unsafe block, a lambda, a call’s arguments - so each is entered and left in pairs, rather than set once for the item. An item with no body leaves this Default.

Fields§

§current_loop: Option<Loop>§lambda_stack: Vec<LambdaContext>

When resolving lambda expressions, we need to keep track of the variables that are captured. We do this in order to create the hidden environment parameter for the lambda function.

§unsafe_block_status: UnsafeBlockStatus§in_unconstrained_args: bool

True if we are elaborating arguments of a function call to an unconstrained function.

§silence_field_visibility_errors: usize

If greater than 0, field visibility errors won’t be reported. This is used when elaborating a comptime expression that is a struct constructor like Foo { inner: 5 }: in that case we already elaborated the code that led to that comptime value and any visibility errors were already reported.

§lvalue_index_counter: usize

Counter used to define temporary variables for non-simple indexes in l-values.

For example, this expression:

array[x + y] = 10;

is transformed into:

let i_0 = x + y;
array[i_0] = 10;
