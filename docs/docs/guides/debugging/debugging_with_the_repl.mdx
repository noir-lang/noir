#### Pre-requisites

In order to use the REPL debugger, first you need to install recent enough versions of Nargo.

## Debugging a simple program

Let's debug a simple program:

```rust
fn main(x: Field, y: pub Field) {
    let z = double(x);
    assert(z != y);
}

fn double(x: Field) -> Field {
    let two = 2;
    x * two
}
```

with a `Prover.toml` of:

```toml
x = "3"
y = "2"
```

To start the REPL debugger, using a terminal, go to the Noir project's home directory. Then:

`$ nargo debug`

You should be seeing this in your terminal:

```
Debugger started. Type 'help' for commands.
At src/main.nr:2 in main
      1 | fn main(x: Field, y: pub Field) {
->    2 |     let z = double(x);
      3 |     assert(z != y);
      4 | }
debug>
```

The debugger displays the current Noir code location, with `->` marking the statement that is about to run, and it is now waiting for us to drive it.

Let's first take a look at the available commands. For that we'll use the `help` command.

```
debug> help
Commands:
  s, step         Step into next statement
  n, next         Step over (skip function calls)
  o, out          Step out of current function
  c, continue     Continue until breakpoint
  v, vars         Show local variables
  bt, stacktrace  Show call stack
  b, break <N>    Set breakpoint at line N
  d, delete <N>   Delete breakpoint at line N
  bp, breakpoints List all breakpoints
  r, restart      Restart debugging from the beginning
  q, quit         Stop debugging
  h, help         Show this help
```

We can inspect the current state of local variables with the `vars` command. At the entry point of the program the only variables in scope are the arguments to `main`, whose values come from `Prover.toml`:

```
debug> vars
  x: Field = 0x03
  y: Field = 0x02
```

The statement we are stopped at calls `double`. Let's use `step` to follow the call into that function:

```
debug> step
At src/main.nr:7 in double
      4 | }
      5 |
      6 | fn double(x: Field) -> Field {
->    7 |     let two = 2;
      8 |     x * two
      9 | }
```

`stacktrace` shows how we got here:

```
debug> stacktrace
#0  double at src/main.nr:7:5
#1  main at src/main.nr:2:13
```

Now `next` executes the current statement and stops at the following one in the same function. Stepping once brings `two` into scope:

```
debug> next
At src/main.nr:8 in double
->    8 |     x * two
debug> vars
  two: Field = 0x02
  x: Field = 0x03
```

We have seen enough of `double`; `out` runs until it returns and stops back in `main`, where its result is now bound to `z`:

```
debug> out
At src/main.nr:3 in main
      1 | fn main(x: Field, y: pub Field) {
      2 |     let z = double(x);
->    3 |     assert(z != y);
      4 | }
debug> vars
  x: Field = 0x03
  y: Field = 0x02
  z: Field = 0x06
```

Since `z == 6` and `y == 2`, the assertion should succeed. Let's continue to the end:

```
debug> continue
Program completed. Return value: ()
```

Had the assertion failed, the debugger would have printed the failure along with its location and call stack instead.

We just went through the basics of debugging using Noir REPL debugger. For a comprehensive reference, check out [the reference page](../../tooling/debugger/debugger_repl.mdx).

## Breakpoints

Rather than stepping one statement at a time, you can set a breakpoint on a line of the current file and `continue` up to it:

```
debug> break 3
Breakpoint set at src/main.nr:3
debug> continue
Breakpoint hit.
At src/main.nr:3 in main
->    3 |     assert(z != y);
```

`breakpoints` lists the breakpoints you have set and `delete 3` removes this one.

## Debugging a test function

Let's debug a simple test:

```rust
#[test]
fn test_simple_equal() {
    let x = 2;
    let y = 1 + 1;
    assert(x == y, "should be equal");
}
```

To debug a test function using the REPL debugger, navigate to a Noir project directory inside a terminal, and run the `nargo debug` command passing the `--test-name your_test_name_here` argument.

```bash
nargo debug --test-name test_simple_equal
```

After that, the debugger has started and works the same as debugging a main function, you can use any of the above explained commands to control the execution of the test function.

### Test result

Once the test function finishes (or you `quit` the session), the test result is printed:

```text
$ nargo debug --test-name test_simple_equal
Debugger started. Type 'help' for commands.
At src/main.nr:13 in test_simple_equal
->   13 |     let x = 2;
debug> continue
[simple_noir_project] Testing test_simple_equal ... ok
```
