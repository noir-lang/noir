# Debugger Known Limitations

import Experimental from '@site/src/components/Notes/_experimental.mdx';

<Experimental />

The debugger runs your program through the Noir interpreter rather than through the compiled circuit, which has a few consequences.

## The program is interpreted, not compiled

The debugger executes the type-checked source of your program directly. It does not generate ACIR or Brillig, so it cannot show you opcodes, the witness map, or unconstrained VM memory, and it cannot write an execution witness when the program finishes. Use `nargo execute` to produce a witness.

Because no circuit is generated, behaviour that only exists after compilation (for example the exact set of constraints the SSA optimizer produces) is not observable from the debugger.

## Unsupported operations

The interpreter does not implement every builtin or blackbox function that the compiled program can use. If your program reaches one of these, the debugger reports an error at that statement and stops.

## Test functions with arguments

Tests that take arguments (fuzz tests) cannot be debugged; only argument-less `#[test]` functions can be selected with `--test-name`.
