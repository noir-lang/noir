## Running the REPL debugger

`nargo debug [OPTIONS]`

Runs the Noir REPL debugger on the `main` function of the selected package, or on a test function when `--test-name` is given.

### Options

| Option                                | Description                                                                          |
| ------------------------------------- | ------------------------------------------------------------------------------------ |
| `-p, --prover-name <PROVER_NAME>`     | The name of the toml file which contains the inputs for the prover [default: Prover] |
| `--package <PACKAGE>`                 | The name of the package to debug                                                     |
| `--test-name <TEST_NAME>`             | Name (or substring) of the test function to debug                                    |
| `--oracle-resolver <ORACLE_RESOLVER>` | JSON RPC url to solve oracle calls                                                   |
| `-h, --help`                          | Print help                                                                           |

`nargo debug` also accepts the compile options shared with `nargo compile` (for example `--deny-warnings`).

None of the debugger commands write files: the program is interpreted, so no execution witness is produced.

## REPL commands

The debugger stops before the first statement of the function being debugged and shows a `debug>` prompt. At every stop it prints the current location and a few lines of surrounding source, with `->` marking the line about to execute:

```
At src/main.nr:2 in main
      1 | fn main(x: Field, y: pub Field) {
->    2 |     assert(x != y);
      3 | }
debug>
```

Every command has a one or two letter shorthand.

### Stepping

#### `step` (s)

Execute the current statement and stop at the next one, entering any function called along the way.

#### `next` (n)

Execute the current statement and stop at the next statement in the current function, stepping over function calls.

#### `out` (o)

Continue until the current function returns, then stop at the next statement in the caller.

#### `continue` (c)

Continue execution until the next breakpoint, or the end of the program.

#### `restart` (r)

Interrupts execution, and restarts a new debugging session from scratch.

#### `quit` (q)

Stops debugging. When debugging a test, the test result is reported after the session ends.

### Breakpoints

Breakpoints are set by line number, in the file the debugger is currently stopped in.

#### `break <line>` (b)

Sets a breakpoint at the given line of the current file:

```
debug> break 12
Breakpoint set at src/main.nr:12
```

Running [the `continue` command](#continue-c) at this point causes the debugger to execute the program until the first statement on line 12 is reached:

```
debug> continue
Breakpoint hit.
At src/main.nr:12 in foo
```

#### `delete <line>` (d)

Deletes the breakpoint at the given line of the current file.

#### `breakpoints` (bp)

Lists every breakpoint, across all files.

### Inspection

#### `vars` (v)

Shows the variables visible at this point in execution, with their type and current value:

```
debug> vars
  x: Field = 1
  y: Field = 2
```

Variables come straight from the interpreter, so anything the program can see, including values reached through references, is shown with its current value.

#### `stacktrace` (bt)

Displays the current call stack, innermost frame first:

```
debug> stacktrace
#0  bar at src/main.nr:15:5
#1  foo at src/main.nr:9:5
#2  main at src/main.nr:3:5
```

### Help

#### `help` (h)

Lists the available commands.
